The end state

Agents that know what they don't know.

Today every agent step goes to the biggest model, because no model can tell whether it's out of its depth. We think the next capability isn't a bigger model. It's a model that knows its own limits, and only then escalates, delegates, or asks.

K2 Cascade is the first measurement toward that: which steps need a big model, and could the small one have known?

Why K2 Horizon

Size is the only variable.

Six sizes, one tokenizer, one chat template, one tool-call format, one training recipe. Released fully open on Sept 3.

Each step goes to the smallest model first. A verifier checks it. On failure, the next size takes over.

Every attempt is one line in a file. The trace file is the dataset.

What the traces say

Same plan at every size. The gap is in the arguments.

  • All three sizes: run tests → read source → read tests → write → run tests → done
  • 0.9B picks the right tool every time, then invents paths like /workspace and repeats itself
  • 3.7B takes the one code-writing step and hands back
  • 375B once narrated an action without calling a tool; the runner now rejects that

Next

Move the signal inside the model.

  • Today the "you can't do this step" signal lives outside: rules plus a 375B judge
  • Next week: score the 375B's outputs token by token with the 3.7B to map where its advantage sits
  • Then: a probe on the 3.7B's hidden state that predicts failure before it acts
  • When the internal signal matches the external judge, the judge disappears. That's an agent that knows its limits.
